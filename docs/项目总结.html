01 概览

一个常驻菜单栏的截图工具，全局快捷键触发，支持两种工作模式与标注、钉图、自动保存。

⚡ 快捷模式（默认 ⌥A）

框选 → 截图 → 直接复制到剪贴板。不保存、不打扰，主打一个快。

✏️ 正常模式（默认 ⌥S）

框选 → 截图 → 进入标注编辑器：直线 / 箭头 / 方框 / 文字，再复制 / 保存 / 钉图。

功能清单

区域框选

全屏遮罩 + 十字光标，实时尺寸显示。

标注工具

直线、箭头、方框、文字，撤销（⌘Z）。

钉图 📌

浮动置顶，可拖动 / 滚轮缩放 / Esc·双击·右键关闭。

白色圆角边框

可选开关 + 宽度滑块，等宽白框。

自定义快捷键

全局键 + 工具栏键（1/2/3）均可在设置里改。

自动保存

保存目录可配置，点保存直接落盘不弹框。

05 关键技术点

几个容易踩坑、值得说明的实现细节。

① Retina 全分辨率，绝不发虚

不让 ScreenCaptureKit 的 sourceRect 帮忙裁剪（它会先按「点」取图再缩放，导致模糊）。改为整屏按全像素截取，再用 CGImage.cropping 做像素级裁剪，零重采样。

// 输出像素 = 点尺寸 × backingScaleFactor
config.width  = Int(screen.frame.width  * scale)
config.height = Int(screen.frame.height * scale)
let full = try await SCScreenshotManager.captureImage(...)
return full.cropping(to: pixelRect)   // 纯像素拷贝

② 坐标系换算

AppKit 用左下角为原点，ScreenCaptureKit / CGImage 用左上角。框选得到的全局坐标要先转成屏幕局部坐标，再翻转 Y，再乘以 scale 才是像素裁剪区。

③ 全局快捷键用 Carbon

RegisterEventHotKey 是系统级、无需「辅助功能」权限，菜单栏 accessory 应用也能用。封装在 HotKeyManager 里，用一个 C 回调按 id 分发到对应 handler。

④ 标注合成导出

标注用「屏幕局部点坐标」存储；导出时建一张 NSBitmapImageRep，rep.size 设为点尺寸、像素数设为 点 × scale，于是绘制按点坐标走、输出却是全分辨率，截图与标注一次性合成。

⑤ 钉图窗口

borderless + .floating 层级的 NSWindow，自己处理 mouseDragged 移动、scrollWheel 缩放、cancelOperation(Esc) / 双击 / 右键关闭。由 AppDelegate 用数组持有，防止被释放。

06 签名与权限（重点）

这是开发期最折腾、也最值得记录的一块。

问题：每次重新编译后，系统都重新索要「屏幕录制」权限。

原因：macOS 的屏幕录制授权绑定在 app 的代码签名身份上。临时签名（ad-hoc）没有稳定身份，TCC 只能用二进制哈希 cdhash 记授权 —— 每次改代码重编，cdhash 变了，系统就当成新 app，权限失效。

解决：用一个固定的自签名证书

  1. 用 openssl 生成自签名证书（带 Code Signing 用途）

    生成私钥 + 自签名证书，打包成 .p12（注意用 legacy 算法，否则 macOS security 验不了）。

  2. 导入登录钥匙串

    security import ss.p12 -k login.keychain-db -T /usr/bin/codesign，得到名为 ScreenShot Dev Cert 的身份。

  3. build.sh 用它签名

    找得到证书就用它，否则回退临时签名。

  4. 授权一次，永久生效

    「指定要求」绑定的是证书指纹 + Bundle ID（不含 cdhash），之后随便重编都不再掉权限。

# build.sh 里的签名逻辑
SIGN_ID="ScreenShot Dev Cert"
if security find-certificate -c "$SIGN_ID" >/dev/null 2>&1; then
  codesign --force --deep --sign "$SIGN_ID" "$APP"
else
  codesign --force --deep --sign - "$APP"   # 回退临时签名
fi

验证绑定关系（这条「指定要求」只认证书 + BundleID）：

$ codesign -d --requirements - ScreenShot.app
designated => identifier "com.prototype.screenshot"
            and certificate leaf = H"a3e05d…"
codesign 老问钥匙串密码？ 那是私钥的访问控制没放行 codesign。弹框时输入登录密码并点 始终允许（不是「允许」），即可永久免密。
安全说明：这个自签名证书没有被设为系统受信任根（那会削弱系统信任模型）。签名本身不需要信任，TCC 也照样能稳定识别 —— 这是最干净的本地开发方案。

07 后续：打包成 DMG 分发

想发给别人用、不上架 App Store，标准路径是 Developer ID 签名 + 公证 + DMG。

步骤说明
① 加入开发者计划Apple Developer Program，$99/年。否则别人下载会被 Gatekeeper 拦截。
② Developer ID 证书后台申请 Developer ID Application 证书，替换现在的自签名证书。
③ hardened runtime 签名codesign --options runtime --sign "Developer ID Application: …"
④ 制作 DMG用 create-dmg 或 hdiutil 打包成磁盘镜像。
⑤ 公证（Notarization）xcrun notarytool submit 上传给 Apple 自动审核（几分钟）。
⑥ 装订（Staple）xcrun stapler staple 把公证票据钉到 DMG/app，离线也能验证。
# 1) 用 Developer ID 重新签名（hardened runtime）
codesign --force --deep --options runtime \
  --sign "Developer ID Application: Your Name (TEAMID)" ScreenShot.app

# 2) 做一个 DMG（brew install create-dmg）
create-dmg --volname "ScreenShot" --app-drop-link 380 120 \
  ScreenShot.dmg ScreenShot.app

# 3) 公证
xcrun notarytool submit ScreenShot.dmg \
  --apple-id "you@example.com" --team-id TEAMID \
  --password "app-专用密码" --wait

# 4) 装订票据
xcrun stapler staple ScreenShot.dmg
对这个工具而言，DMG 是更省事的分发方式 —— 不用进沙盒，全局快捷键、ScreenCaptureKit、任意目录保存都能照常工作。

08 后续：上架 Mac App Store

App Store 强制 App Sandbox（沙盒），对这类系统级工具有几处需要改造。

能力沙盒下情况需要做的
屏幕录制可用用户授权即可，ScreenCaptureKit 支持沙盒。
全局快捷键受限RegisterEventHotKey 在沙盒内可用，但 Carbon 已弃用；建议迁到现代方案或评估风险。
任意目录保存受限沙盒禁止直接写任意路径。须用 NSOpenPanel 让用户授权，并保存安全作用域书签（security-scoped bookmark）持久化访问权。
钉图浮动窗可用无需改动。
菜单栏 accessory可用LSUIElement 允许上架。

上架流程

  1. 开通开发者计划 + 创建 App ID

    在 App Store Connect 注册 App，配置 Bundle ID。

  2. 开启 App Sandbox 并配置 entitlements

    勾选屏幕录制、用户选择文件读写等权限；把保存目录改为安全作用域书签。

  3. 用 Apple Distribution 证书 + 描述文件签名

    Apple Distribution 证书 + App Store 的 provisioning profile。

  4. 准备素材

    App 图标（含 1024×1024）、截图、隐私政策、分级信息。

  5. 用 Xcode / altool 上传并提交审核

    Archive → 上传 → App Store Connect 填写元数据 → 提交人工审核。

当前项目改造量评估： 最大的两块是 ——（1）把固定保存目录改成安全作用域书签；（2）评估 Carbon 全局快捷键在审核中的接受度。其余功能基本可平移。整体而言，这类工具走 DMG 直分发更顺；要触达普通用户再考虑 App Store。
